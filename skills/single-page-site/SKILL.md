# Ultimate Single-Pager Studio — Agency-Grade (Zero-Dependency, CSS-3D, Local SEO)

## Mission

One short prompt (just the client's business info) → **ONE `.html` file** that stands beside work agencies charge six figures for: premium art direction, editorial composition, real CSS-3D depth, tasteful scroll choreography, and the full local-SEO stack — with **zero external dependencies**. The file renders perfectly from a double-click, offline, with every icon, font, animation, and map built in by hand. Images are generated in the background **in parallel** with the build, then wired in as **HOSTED LINKS** (anonymous free host by default; client hosting when provided).

The skill does the thinking: you never write the site structure, the copy, the SEO, the design direction, or the 3D/motion plan. You supply only what only you know — the client's business facts.

**The three non-negotiable core principles (never trade these for looks):**
1. **HTML stack** — exactly ONE `.html` file; all CSS and JS inline; no build step, no backend, no server.
2. **Zero external dependencies** — no CDN links, no webfonts, no icon fonts, no external embeds, no analytics, no third-party scripts of any kind. Icons are hand-built inline SVG; typography uses curated system font stacks; the map is a hand-built inline SVG. The only network requests the page may make are the `<img src>` image URLs themselves.
3. **SEO rules** — the full local-SEO stack baked into the head (title/meta/OG/Twitter/robots/canonical), JSON-LD (Business + FAQPage + Breadcrumb), one H1 mirroring the keyword, strict H1-H3 hierarchy, lazy-loaded images with alt/width/height.

## Workflow at a glance

1. **Phase 1 — Intake:** collect ONLY the client's business information (one compact list).
2. **Phase 2 — Content + SEO engine:** the skill writes the full section outline, every word of copy (1,500+ words), the primary keyword, and the complete head/JSON-LD SEO blueprint.
3. **Phase 3 — Build:** start the image pipeline FIRST (background, parallel), then design and hand-code the HTML/CSS/JS to the Agency Standard below (art direction → design system → 3D depth → motion → icons → copy), auto-integrate the hosted image URLs, run the mandatory SEO + taste + feature self-check, and deliver.

## Phase 2 — Content & SEO engine (skill writes this, never asks)

### 2.1 Primary keyword

Derive ONE primary keyword: `<core service> in <City>` — e.g. "home tuition in Jaipur", "café in Chakala", "gold jewellery in Alwar", "bike service in Dehradun". Pick the single most valuable search phrase for this business. Everything below hangs off it. The page must also naturally carry the three local-SEO variants somewhere in the copy: **"Best {Service} in {Location}"**, **"Best {Service} in {City}"**, **"Best {Service} in {State}"** — at least two of the three as literal phrases, the third as a natural variant.

### 2.2 The 10-section outline — write real copy for each

1. **Home (hero)** — **full-width hero** with CSS-3D depth (layered image plane, floating headline, parallax), brand name (loudest text), one-line promise, primary CTA (call / WhatsApp / visit)
2. **About Us** — the story, the people, the place; specific and human, not generic. Must include an attractive image card / image box (optionally a 3D tilt card)
3. **Services** — **at least 6 service cards**, each with its **own image** AND a hand-built inline SVG icon, a short name and a real one-line description
4. **Why Choose Us** — 4–6 concrete differentiators (experience, quality, price, service, warranty, local presence)
5. **FAQ** — 6–8 real questions customers actually ask, each with a genuine answer (this section MUST exist and match the FAQPage JSON-LD)
6. **Testimonials** — 3–5 believable reviews with names; use realistic local names (never "John Doe"), no invented URLs, no star-count inflation
7. **Gallery** — 6–8 images (AI-generated or client photos), laid out as an asymmetric editorial grid
8. **Map** — a **hand-built inline SVG map** (brand-styled pin, roads, locality labels — the zero-dependency way); if the client explicitly opts into the Google Maps embed, that is the only permitted iframe in the entire file
9. **Contact Us** — full contact block (phone, WhatsApp, email, address, hours) + the **WhatsApp enquiry form** (Name, Phone, Email, Service, Message — submit composes a `wa.me` message via JavaScript, no backend/PHP)
10. **Footer** — social media icons (inline SVG), quick links, contact details, copyright line, and the exact MBG Card credit (see §3.2)

Plus a **Service Areas** band (local-SEO signal): the localities list — folded into "Why Choose Us" or its own strip.

### 2.3 Copy rules

- **1,500+ words minimum** across the page — thin pages don't rank. Write specific, local copy.
- **Keyword discipline:** repeat the exact primary keyword phrase throughout; put it in **≥ 2 H2/H3 headings**; aim for **≥ 1.5% keyword density**; name the **city repeatedly** in the copy; work in the "Best … in {Location/City/State}" variants naturally.
- No lorem ipsum, no filler, no clichés ("elevate", "seamless", "unleash", "next-gen"). Write like a good local business talks.
- One copy register across the page — consistent voice.
- **Zero em-dashes.** Use hyphens, commas, colons, or periods. An em-dash anywhere in the copy is a failure.
- Cut ruthlessly: every sentence must earn its place. If deleting 30% improves the page, keep deleting.

### 2.4 SEO blueprint (baked into the `<head>`)

| Item | Requirement (exact) |
|---|---|
| **Title** | `Best <primary keyword> | <Brand>` — keyword-first (e.g. `Best Home Tuition in Jaipur | Shiksha Tutors`) |
| **Meta description** | 50–320 chars, the keyword in the first 160 |
| **Robots** | `<meta name="robots" content="index, follow, max-snippet:-1, max-image-preview:large, max-video-preview:-1">` — verbatim |
| **Canonical** | `<link rel="canonical" href="https://<client-domain>/">` (use the real domain if provided, else a placeholder `.in` domain they can swap) |
| **Open Graph** | ≥ 6 tags: `og:title`, `og:description`, `og:type`, `og:url`, `og:locale`, `og:site_name` (+ `og:image` as the hero hosted URL) |
| **Twitter card** | `twitter:card` = `summary_large_image`, `twitter:title`, `twitter:description`, `twitter:image` |
| **H1** | EXACTLY one, mirroring the title: `Best <keyword> in <City>` (not a slogan) |
| **H1–H3 hierarchy** | One `<h1>`; every major section gets an `<h2>`; sub-blocks use `<h3>`; nothing skips a level |
| **JSON-LD Business** | correct `@type` for the industry (LocalBusiness, Restaurant, JewelryStore, AutoRepair, HomeAndConstructionBusiness, …) with name, address, geo, phone, hours, image, url |
| **JSON-LD FAQPage** | must match the on-page FAQ verbatim |
| **JSON-LD BreadcrumbList** | 2–3 items (Home → Services) |
| **Images** | every `<img>`: descriptive `alt`, explicit `width`/`height`, `loading="lazy"` (except hero) |

### 2.5 Image plan

Before building, assign each visual slot an aspect from the ratio table (§3.8) and a one-line art direction (subject + setting + palette, filled into the prompt template). Typical slot list for the full spec: `hero` (16:9), `about` (4:3), `service-1 … service-6` (square), `gallery-1 … gallery-6` (square/mixed). This becomes the `site-images.json` spec the background pipeline runs (§3.8).

## Phase 3 — Build

### 3.1 Art direction — the agency standard (read this before writing any code)

Design like a senior studio lead, not a template. Before writing HTML, commit to a **visual thesis** (one sentence: mood + material + energy), a **content plan** (hero → support → detail → final CTA), and a **signature element** — the ONE thing this page is remembered by. Every layout, color, and motion decision below hangs off that thesis.

**Design read first:** name the page kind (local business / studio / restaurant / service), the audience, and the single job of the page. Then pick a direction deliberately. State the read in one line before building ("Reading this as: a family jeweller's one-pager for local buyers, warm editorial language, heritage-modern composition").

#### 3.1.1 Composition playbook — vary the layout families

Use these families; **never repeat the same family for two adjacent sections** and use at least 4 different families across the page:

- **Full-bleed image hero** — edge-to-edge image, brand name as the loudest text, narrow calm text column anchored to a quiet area of the image. The hero runs edge-to-edge with no inherited gutters; only the inner text column is constrained.
- **Asymmetric split** — text on one side, image on the other, generous whitespace, deliberate imbalance (60/40, 55/45 — never a flat 50/50 unless the brief demands it).
- **Editorial manifesto** — large type as the dominant visual, almost-poster, no asset or a small one; powerful for About / Why Choose Us.
- **Bento grid** — asymmetric tile grouping with real visual variation in at least 2-3 cells (image, tint, pattern); never 6 identical white cards.
- **Editorial gallery** — asymmetric offsets, varied aspect ratios, captions that earn their place.
- **Full-width quote / statement band** — one line of large type, generous space around it.

**Anti-default discipline:** no centered hero over dark mesh, no three identical feature cards, no generic SaaS card grid as the first impression, no glassmorphism on everything. If a layout reads like what any AI would do for any business, change it.

#### 3.1.2 The signature element

Spend your boldness in ONE place. Pick one memorable device this page is known for, keep everything else quiet and disciplined:

- a 3D floating product/brand mark that tilts with the cursor (§3.4)
- a scroll-pinned hero where content choreographs past a fixed image (§3.5)
- an oversized editorial numeral or monogram used as structure
- a marquee strip of the services/values that pauses on hover (§3.5)
- a spotlight/brand-colored glow that follows the cursor across one section

Everything else is restraint: generous whitespace, calm surfaces, one accent color, two typefaces max.

#### 3.1.3 Reference sites — study them when online, then design ORIGINAL, not copies

- https://wellnesssupermarket.in/
- https://blackbullcafechakala.com/
- https://aravalijewellers.com/
- https://mahadevautomobiles.com/
- https://arnikacollection.in/
- https://valoraappliance.com/

Extract what makes them work: photography-led heroes, editorial type, authentic local copy, one confident brand colour, real products in frame, calm whitespace. Then make something that stands beside them, not behind them.

**Competitor research:** when online, find 3–5 direct competitors of the client, note the winning pattern in each (hero, proof, layout, tone), and deliberately design **better** on at least three of those dimensions. When offline, skip gracefully — never block the build.

**Anti-slop rules (hard):** no AI-purple gradients or generic SaaS card grids; no beige-cream + serif + terracotta default unless the brand genuinely is that; no near-black + acid accent default; no glossy glassmorphism everywhere; no em-dashes in copy; no "Trusted by / 100+ happy customers" fake-proof strips unless real; no fake-precision numbers; no generic names; no AI-gradient "slop" backgrounds; no div-built fake screenshots; no version labels in the hero; no scroll-cue arrows ("scroll to explore"); no decorative status dots. If a choice reads like what any AI would do for any business, change it.

### 3.2 Hard constraints (non-negotiable)

- Exactly ONE `.html` file: HTML + internal CSS + internal JavaScript. **No external files, no CDNs, no build step, no backend/PHP.**
- **Zero external resources.** No Font Awesome, no Google Fonts, no icon fonts, no analytics, no tracking, no third-party scripts, no external embeds. Everything ships inside the file:
  - Icons = hand-built inline SVG (see §3.6).
  - Typography = curated system font stacks (see §3.3.1). Never `@import` or `<link>` a webfont.
  - Map = hand-built inline SVG (see §3.7).
- **The ONLY permitted external exceptions in the entire file:**
  1. `<img src="https://…">` image URLs (hosted images — required by the workflow), and
  2. the Google Maps embed **if and only if** the client explicitly opts in (never by default — the inline SVG map is the default).
  No other anchors, iframes, or URLs — contact links (`tel:`, `mailto:`, `https://wa.me/`) are the only allowed external anchors. JSON-LD `url`/`sameAs` metadata is fine — it's metadata, not an embed.
- **Images are HOSTED and referenced by URL** — never data URIs, never local folder paths in the final file (that's the client's workflow). The URLs come from the `images/` folder convention, a provided base URL, or an auto-uploaded free host (§3.8).
- Responsive (mobile-first, desktop/tablet/mobile), semantic HTML, valid CSS, keyboard-accessible, visible focus, `prefers-reduced-motion` respected.
- **Floating WhatsApp button** — fixed position, visible across the ENTIRE website at every scroll position, links to `https://wa.me/<digits>` with a pre-filled message, styled as a recognizable WhatsApp circle (inline SVG), with an accessible label.
- **Contact form** — Name, Phone, Email, Service, Message; on submit it composes the enquiry into a WhatsApp message and opens `wa.me/<digits>?text=<encoded>` via JavaScript. No backend. Validate fields with native HTML5 + a little JS; show a clear inline message when the number is missing.
- **Footer — exact line** (compute the year with one inline JS line, e.g. `<span id="yr"></span>` set to `new Date().getFullYear()`):
  `© Copyright {current year} | All Rights Reserved | Powered by MBG Card Pvt. Ltd.`
  Plus: social media icons (inline SVG, `aria-label`ed), quick links (anchor to in-page sections), and contact details.
- **Deliverable = the `.html` file + an `images/` folder** (the files the URLs point at) + `images-manifest.json` (which URL goes where).

### 3.3 The design system (build these tokens first, then every component uses them)

#### 3.3.1 Typography — premium without webfonts (zero-dependency)

Use curated **system font stacks** and win with scale, weight, tracking, and spacing instead of novelty fonts. Two faces max: a display face and a body face.

- **Display (headlines):** `"SF Pro Display", "Segoe UI", system-ui, -apple-system, "Helvetica Neue", Arial, sans-serif` for a clean modern feel, or — when the brand is heritage/editorial — pair a system serif for display: `Georgia, "Times New Roman", serif` used with tight tracking and weight contrast (only if the brand genuinely suits it; sans is the default).
- **Body:** `system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`.
- **Mono (optional, for data/meta accents):** `"SF Mono", "Cascadia Code", Consolas, monospace` — use sparingly for labels, numbers, addresses.
- **Scale discipline:** hero display `clamp(2.4rem, 6vw, 4.5rem)` with `letter-spacing: -0.03em` and `line-height: 1.05`; section H2 `clamp(1.8rem, 3.5vw, 2.6rem)`; body `1rem–1.0625rem` with `line-height: 1.6`; labels/eyebrows `0.75rem`, uppercase, `letter-spacing: 0.14em` (max ONE eyebrow per 3 sections — never above every heading).
- **Hierarchy via weight and color, not just size.** Body text never pure black — use `#1a1a1a`-ish ink; secondary text a muted `#6b6b6b`-ish gray. Never `#000` and never `#fff` — always off-black / off-white.

#### 3.3.2 Color — one accent, disciplined neutrals

- Pick the palette from the brand's world (the subject's materials, a signature dish, the shop front). Derive: 1 **accent** (used ONLY for CTAs, active states, highlights — saturation under 80% by default), 2–3 **neutrals** (background, surface, ink), and one **tint** (accent at low opacity for section backgrounds).
- Name the tokens semantically in CSS custom properties (`--bg`, `--surface`, `--ink`, `--muted`, `--accent`, `--line`). No raw hex in components.
- One palette for the whole page. No warm/cool gray mixing. Dark mode: if you build both, use `prefers-color-scheme` and keep hierarchy parity (the accent stays recognizable in both).
- Backgrounds should not feel empty: use subtle full-width imagery at low opacity, a soft radial light spot in the brand tint (`radial-gradient` at opacity 0.03–0.06), or a fine geometric line pattern — never loud gradients.

#### 3.3.3 Spacing, shape, elevation

- **Whitespace is the luxury.** Generous section padding (`clamp(4rem, 9vw, 7rem)`), tight internal rhythm (8px grid). Let sections breathe.
- **One corner-radius language** for the page: sharp (0–6px) for editorial/technical, softly rounded (12–16px) for warm/consumer, pill only for buttons/tags. Never mix round buttons with square cards.
- **Shadows are whisper-soft, tinted to the background hue** — `0 2px 8px rgba(0,0,0,0.05)` type, never pure-black heavy drops. Use elevation only where it communicates hierarchy; otherwise group with hairlines (`1px solid var(--line)`) and space.
- **Texture:** a fixed, `pointer-events-none` grain/noise overlay at opacity 0.02–0.04 across the hero (SVG feTurbulence data URI is fine — it ships inline) removes digital sterility. Never on scrolling containers.

### 3.4 CSS-3D depth system — the "expensive" layer, zero dependencies

Real depth sells premium. All 3D is pure CSS (`perspective`, `transform-style: preserve-3d`, `translateZ`, `rotateX/Y`) plus a few lines of JS — no libraries, no WebGL. Build depth into at least the hero and one other section:

**Rules:**
- Animate ONLY `transform` and `opacity` — never `top/left/width/height`.
- Use `perspective` on the parent, `transform-style: preserve-3d` on the stage, and move child planes with `translateZ` (positive floats up, negative sinks back).
- Every 3D/motion effect must collapse to static under `prefers-reduced-motion`.
- Use `will-change: transform` sparingly, only on elements that actually animate.
- No `window.addEventListener("scroll", ...)` for parallax — use the native **CSS scroll-driven animations** (`animation-timeline: view()`) or an IntersectionObserver with transform updates (rAF-throttled).

**Signature 3D devices (pick the ones that fit the thesis):**
1. **Parallax hero stack** — three planes at different `translateZ` (image `z:-1` with scale, headline `z:0`, CTA `z:1`); on scroll the planes drift at different rates via scroll-linked transforms. Calm, never seasick.
2. **Tilt card** — services/About cards that rotate `rotateX/rotateY` toward the cursor (JS: mousemove → transform, with a glare highlight that moves opposite). Add `transform-style: preserve-3d` and let an icon/photo `translateZ(24px)` pop out of the card face.
3. **Floating brand mark / product** — the hero's visual gently bobs (slow CSS keyframes, 6–10s ease-in-out) with a soft shadow that moves opposite — sells physical weight.
4. **Scroll-driven 3D reveal** — a band that rotates from `rotateX(12deg)` flat into place as it enters view (`animation-timeline: view()` or IntersectionObserver adding a class).
5. **Depth-stacked gallery** — editorial gallery where some tiles are `translateZ(30px)` (pop forward) and others `translateZ(-20px)` with slight blur — a physical pinboard feel.
6. **Marquee band** — services/values scrolling horizontally, pausing on hover, masked with a fade at the edges.

Only ship 3D that serves the story — a jeweller's ring floating in the hero is earned; a random cube is not.

### 3.5 Motion choreography — 2–3 intentional moments, not noise

Ship at least 2–3 intentional motions, exactly the ones your thesis calls for:

- **One entrance sequence in the hero** — headline lines rise in staggered (opacity 0 → 1, `translateY(24px) → 0`, 600ms, `cubic-bezier(0.16, 1, 0.3, 1)`, 80ms cascade per element). Never mount everything at once.
- **One scroll-linked moment** — section reveals via IntersectionObserver (fade + 12px rise, `once: true`, 120ms cascade for grids), or a pinned/sticky element, or the scroll-driven 3D band.
- **One hover micro-interaction** — buttons push (`scale(0.98)` on `:active`), cards lift 1–2px with a whisper shadow, the tilt card's glare, the marquee pausing.
- **Motion rules:** fast and restrained (150–300ms hover, 600–800ms entrances); exit faster than enter; consistent easing across the page; every animation justifiable in one sentence (hierarchy / storytelling / feedback). Motion claimed = motion shown: if you specify it, it must work. `prefers-reduced-motion: reduce` collapses everything to static — non-negotiable.

### 3.6 Iconography — hand-built inline SVG (zero-dependency)

No icon fonts. Build a small coherent icon set as inline `<svg>` (12–20 icons: phone, WhatsApp, email, location pin, clock, each service icon, social icons, chevrons, plus/minus for FAQ).

- **One family:** consistent stroke weight (1.5–1.75), same viewBox (`0 0 24 24`), `fill="none"`, `stroke="currentColor"`, `stroke-linecap="round" stroke-linejoin="round"` — so icons inherit text color.
- Each icon is a tiny inline `<svg>` with `aria-hidden="true"` (decorative) or an `aria-label` when it carries meaning (social links).
- Never emojis as icons. Never hand-copy paths you can't vouch for — compose from primitives (circles, lines, rects, paths) cleanly.
- The WhatsApp button, social icons, service icons, FAQ toggles all come from this set.

### 3.7 The inline SVG map (zero-dependency default)

Build a tasteful inline SVG map instead of the Google embed (unless the client opts in to Google):

- A stylized, brand-palette map: soft surface tone, a few abstract street lines in the neutral, the business at the center with a **pulsing pin** (accent color, subtle 2s pulse keyframe), 3–5 service-area locality labels in the mono/label style, a compass or scale mark for authenticity.
- Add `role="img"` + `aria-label="Map showing {Business} at {Address}"`. Keep the file small (a few KB).
- If the client explicitly wants the real Google Map, use the iframe embed — it is the only permitted iframe in the file — and say so in the summary.

### 3.8 Images — background pipeline + HOSTED links (this is the workflow)

The image engine, model (Nano Banana 2), and ratio mapping are FIXED (same bridge, same Chrome session), so quality is identical no matter who runs it. The skill's prompt discipline controls the rest. **Images are generated IN PARALLEL with the build** and wired in as hosted URLs afterwards — never data URIs, never local paths in the final file.

#### 3.8.1 Kick off the background pipeline (do this FIRST, before writing any HTML)

1. Write `site-images.json` next to your working files:
```json
{
  "slots": [
    { "key": "hero",  "prompt": "<template-filled>", "size": "1792x1024" },
    { "key": "about", "prompt": "<template-filled>", "size": "1536x1024" },
    { "key": "service-1", "prompt": "<template-filled>", "size": "1024x1024" }
  ]
}
```
2. Start the pipeline DETACHED so it keeps running while you build. **Default = anonymous hosting** (auto-upload to catbox.moe — free, no account, real direct hotlink URLs — the client provides no URLs):
```
powershell -NoProfile -Command "Start-Process -FilePath node -ArgumentList 'site-images.mjs','site-images.json','--out','images','--upload' -WindowStyle Hidden"
```
(`site-images.mjs` ships in this skill's folder. Run from the folder that contains your spec, or pass the full script path.) Optional overrides, ONLY when the client has hosting: `--base-url https://client.com/images/` (bakes their URLs, no upload) or plain folder mode (URLs stay `/images/…`, client uploads the folder).

The pipeline: generates each slot through the bridge (one job ≈ 4 candidates), saves them to `images/`, uploads the chosen one per slot, and rewrites **`images/images-manifest.json` after every slot** (`{done, slots: {key: {status, file, url}}}`). The bridge serializes generations (one Chrome tab), so the pipeline runs them back-to-back — that's fine, it's in the background. Expect roughly 30–70s per slot for a 10–14 slot site — Chrome churns while you code.

#### 3.8.2 Build in parallel, then AUTO-INTEGRATE the images (mandatory — this is the point)

Write the full HTML/CSS/copy (§2.3, §3.1–§3.7) **while Chrome churns through the slots**. As you write each `<img>`, give it a placeholder `src=""` plus a `data-slot="<key>"` attribute — the integration happens at the end, automatically:

1. When the page structure is done, read `images/images-manifest.json`.
2. **Not done** → poll: `sleep` in 20–30s steps (each slot ≈ 30–60s) and re-read until done. **Never deliver a page with empty image srcs.**
3. **Done** (`done: true`) → run the deterministic auto-integration script (ships in this skill's folder) instead of hand-editing:
```
node integrate-images.mjs <your-page>.html images/images-manifest.json
```
It fills every `<img src="" data-slot="<key>">` with the manifest URL and removes the markers. Exit 0 = all wired.
4. **Exit 1 (unresolved slots)** → the script prints which slots failed; hand-craft an inline SVG in the page palette for each and note it in the summary.
5. **Delivery gate (hard):** before handing over, scan the final HTML for `src=""` / `src="#"` — if any remain, the integration is NOT finished; complete it first. Every `<img>` must have a real http(s) URL or a data: SVG by the time you deliver.

| Tall (hero on mobile, stories) | `1024x1792` | 9:16 |

#### 3.8.4 On-demand single image (one-off, not the full site)

For a single image (logo variant, social post, ad) use the `generate_image` MCP tool (`flowui` server) — same engine, same template, same quality — and it returns a viewable image block plus a saved file. The pipeline is for full-site batches.

#### 3.8.5 If the bridge is unavailable

Fallback order if `flowui/*` fails: `gflow/nano-banana-2` (session-token bridge, hits Google's daily quota), `antigravity/gemini-3.1-flash-image` (needs Antigravity OAuth + projectId), `lmarena/qwen-image-2.0` (needs a fresh arena.ai session + reCAPTCHA). If ALL image paths fail: **Mode A fallback** — hand-crafted inline SVG art in the page palette, and state in the summary that AI generation was unavailable and why. **Bridge sign-in / down errors:** "needs a one-time sign-in" → run `bridge\flow-browser\re-sign-in.cmd` and sign in, then retry. "Connection refused" → `bridge\flow-browser\start-flow-browser.cmd`.

### 3.9 Mandatory self-check before delivery (the SEO + taste + feature audit)

Run EVERY row before handing over — this is the client's audit, baked in:

**Head & Meta**
- [ ] Title = `Best <keyword> in <City> | <Brand>` (keyword-first)
- [ ] Meta description present, 50–320 chars, keyword in first 160
- [ ] Robots tag verbatim: `index, follow, max-snippet:-1, max-image-preview:large, max-video-preview:-1`
- [ ] Canonical link present
- [ ] Open Graph ≥ 6 tags (title, description, type, url, locale, site_name + image)
- [ ] Twitter card tags (card, title, description, image)

**Headings & Structure**
- [ ] Exactly one `<h1>` that mirrors the title (`Best <keyword> in <City>`)
- [ ] H1–H3 hierarchy: every major section has an `<h2>`, sub-blocks use `<h3>`, nothing skips a level
- [ ] Semantic HTML (header, nav, main, section, article, footer)

**Schema (JSON-LD)**
- [ ] Business block with the correct `@type` (LocalBusiness, Restaurant, …)
- [ ] FAQPage JSON-LD + matching on-page FAQ section
- [ ] BreadcrumbList JSON-LD

**Images**
- [ ] Every image hosted + referenced by URL (client folder, provided base URL, or catbox link) — never a data URI, never a local path
- [ ] Every image: descriptive alt, width/height attrs, lazy loading (hero excepted)
- [ ] No `src=""` / `src="#"` remain anywhere (hard delivery gate)

**Content & Keyword**
- [ ] 1,500+ words, specific local copy
- [ ] Service-areas section listing the localities served
- [ ] Focused, repeated target keyword (≥ 1.5% density)
- [ ] Keyword used in ≥ 2 H2/H3 headings
- [ ] City/location named repeatedly in the copy
- [ ] Local-SEO variants present: "Best {Service} in {Location}" / "Best {Service} in {City}" / "Best {Service} in {State}"

**Client features**
- [ ] Floating WhatsApp button present and visible across the whole page (`wa.me` link, aria-label)
- [ ] Contact form (Name, Phone, Email, Service, Message) submits to WhatsApp via JS — no backend
- [ ] Inline SVG map present (or stated Google-embed opt-in in the summary)
- [ ] Services section has ≥ 6 cards, each with an image AND an inline SVG icon
- [ ] Every major section has an attractive image card / image box
- [ ] Sticky navbar, smooth scrolling, hover effects, entrance animations, professional colour scheme
- [ ] 100% responsive (desktop / tablet / mobile — no horizontal scroll, readable text, tap-friendly targets)

**Taste & depth (the agency bar)**
- [ ] A visual thesis and ONE signature element exist — the page is memorable for one thing
- [ ] At least 4 different layout families across the page; no two adjacent sections share a family
- [ ] CSS-3D depth in the hero (parallax stack or floating mark) and at least one more section
- [ ] 2–3 intentional motions shipped and working (hero entrance, one scroll moment, one hover interaction)
- [ ] Motion uses only transform/opacity; no `window` scroll listeners; `will-change` used sparingly
- [ ] `prefers-reduced-motion` collapses all motion to static
- [ ] One corner-radius language; whisper-soft tinted shadows only; elevation only where hierarchy needs it
- [ ] Typography: two faces max, system stacks, off-black ink, hierarchy via weight+color
- [ ] One accent color used consistently; semantic CSS custom properties for all colors
- [ ] Icons: one hand-built inline SVG family (consistent stroke, viewBox 24, currentColor)
- [ ] No em-dashes anywhere in the copy
- [ ] No AI slop: no purple gradients, no generic 3-card grid, no beige+serif default, no fake proof strips, no version labels, no scroll cues, no decorative dots

**Zero-dependency & footer**
- [ ] NO external CSS/JS/fonts/embeds except the allowed exceptions: hosted `<img>` URLs and (if opted in) the Google Maps iframe — nothing else
- [ ] No external links except `tel:` / `mailto:` / `wa.me` (and the map embed if opted in)
- [ ] `images/` folder + `images-manifest.json` delivered alongside, URLs match the manifest
- [ ] Footer exact line with live year: `© Copyright {year} | All Rights Reserved | Powered by MBG Card Pvt. Ltd.`
